# 数据字典（说明书）

> 本文档说明 `src/parser/parse.py` 从 CS2 demo 解析出的全部结构化数据。
> 数据来源：`awpy 3.3.0`。行数以示例 demo（`Sonkyo_2026-11-16_de_dust2_1.dem`，de_dust2，19 回合）为准，不同 demo 行数不同。
>
> **数据存放位置**：`data/processed/<demo名>/tables/`（Parquet 表 + header.json + manifest.json）。
> 图片在 `<demo名>/figures/`，分析表格在 `<demo名>/reports/`。

---

## 1. 通用约定

| 概念 | 说明 |
|------|------|
| **坐标系统** | Hammer 单位，`x`/`y` 为平面坐标，`z` 为垂直高度（向上为正）。画热力图时需与地图底图对齐 |
| **阵营 `side`** | `terrorist`（T）、`counter-terrorist`（CT）；观察者/机器人可能为 `null` |
| **队伍编号** | 2 = Terrorist，3 = Counter-Terrorist（如 `rounds.winner`） |
| **`steamid`** | Steam 64 位 ID，`0` 表示 GOTV 观察者或机器人 |
| **`tick`** | 游戏刻，demo 按 tick 推进。本 demo 约 64 tick，`tick / 64 ≈ 秒` |
| **`entity_id` / `entity_serial`** | 游戏内实体编号，用于关联同一实体（含道具、炸弹） |
| **编码** | 所有 Parquet 均为 UTF-8，中文昵称安全 |

### 3.2 `players`（本场玩家）

| 字段 | 类型 | 说明 |
|------|------|------|
| `steamid` | UInt64 | Steam ID（**0 = bot 或 GOTV 观战者**） |
| `name` | String | 昵称 |
| `side` | String | 阵营（`terrorist` / `counter-terrorist` / null） |
| `team_clan_name` | String | 战队名（通常为 null） |
| `is_spectator` | Boolean | 是否观战者实体（如 `5EGOTV`） |
| `is_bot` | Boolean | 是否 AI 机器人接管（玩家掉线后由 CS2 补位） |

> ⚠️ **bot 与玩家中途换人**：CS2 中 bot 的 `steamid` 为 0，GOTV 观战者实体同样为 0。
> 本 demo 里玩家 `阿giao先生` 打了 9 回合后掉线，第 10 回合起由 bot `Darryl` 接管到结束，
> 所以 `players` 表有 12 行（9 真人 + 掉线者 + bot + 观战者）而不是 10 行。
> **主键请用 `steamid` 而不是昵称**（换人时同一游戏位置会对应两个不同实体）。
> 所有分析模块默认剔除 `steamid == 0` 的数据。

### 3.8 `round_economy`（回合经济 · awpy 原版）

| 字段 | 类型 | 说明 |
|------|------|------|
| `round_num` | Int32 | 回合号 |
| `side` | String | 阵营 |
| `equipment_value` | Int32 | 装备总价值 |
| `buy_type` | String | 购买类型：`pistol` / `eco` / `force` / `full` |
| `n_players` | Int32 | 该阵营人数 |

> ⚠️ **这一列作者不是本项目，是 awpy 的 Rust 后端**，其实现就是对全队装备总价值做绝对阈值分档
> （`<5000` → eco、`5000~20000` → force、`>=20000` → full；`pistol` 由半场首回合硬标）：
>
> ```rust
> const BUY_ECO_MAX: i32 = 5_000;
> const BUY_FULL_MIN: i32 = 20_000;
> ```
>
> 它不看**可用资金**，也不看**对手强弱**，因此会把「赢下手枪局后第二回合人均 3500 全部花光」
> 误判成 `force`（实际是经济上限内的买满）。本项目因此重算了一套分类：见 3.12。

## 4. 数据流与后续使用

```
demo 文件
   │  awpy (Rust 后端)
   ▼
Parquet 表格（本字典）
   │
   ├─ snapshots_1s ──────────► 走位热力图（阶段 1）
   ├─ kills / damages ───────► 交火 / 死亡热区（阶段 1）
   ├─ rounds + kills ────────► 失守区域判定（阶段 2）
   ├─ grenades / bomb / shots► 战术打法挖掘（阶段 2）
   ├─ item_events + snapshots► 经济局分类 round_economy_v2（阶段 2，`src/analysis/economy.py`）
   ├─ round_economy_v2 + snapshots► 推荐系统 context（阶段 3）
   └─ 全部聚合统计 ──────────► LLM 战术报告（阶段 4）
```

## 5. `item_events`（物品事件）

> 购买 / 丢弃 / 拾取的逐条记录，**`cost` 是真实花费**，是做经济分析的首选数据源。

| 字段 | 类型 | 说明 |
|------|------|------|
| `tick` | Int32 | 事件 tick |
| `action` | String | `purchase`（购买）/ `drop`（丢弃）/ `pickup`（拾取） |
| `steamid` / `name` / `side` | — | 操作者身份（`steamid == 0` 为 bot） |
| `item` | String | 物品名（`ak47` / `kevlar` / `smokegrenade` …） |
| `cost` | Int32 | 该次花费（仅 `purchase` 有值） |
| `entity_id` / `entity_serial` | — | 物品实体编号 |
| `x` / `y` / `z` | Float32 | 位置 |
| `original_owner_steamid` | UInt64 | 原持有者 |
| `near_buy_zone` | Boolean | 是否在购买区内 |

> ⚠️ **bot 的 `cost` 不可信**。例如 bot `Darryl` 的购买事件里 AK 记为 4000（实际 2700）、
> P250 记为 4000（实际 300）。本项目所有经济统计均剔除 `steamid == 0`。

## 6. `round_economy_v2`（经济局分类 · 本项目重算）⭐

由 `python -m src.analysis.economy` 生成，同时输出 `reports/round_economy_v2.csv`。

| 字段 | 类型 | 说明 |
|------|------|------|
| `round_num` | Int32 | 回合号 |
| `side` | String | 阵营 |
| `n_players` | Int32 | 该阵营**真人**人数（bot 已剔除，所以可能 < 5） |
| `buy_type_v2` | String | **本项目的分类**：`pistol` / `eco` / `force` / `full` |
| `awpy_buy_type` | String | awpy 原版分类（对照用） |
| `eco_kind` | String | eco 细分：`eco_pure`（纯手枪省钱）/ `eco_gear`（带着枪省钱） |
| `saved_gear` | Boolean | 是否保枪局（不花钱但手上有长枪） |
| `eq_p` | Float64 | 人均装备值（freeze 末） |
| `eq_opp` | Float64 | 对手人均装备值 |
| `eq_ratio` | Float64 | `eq_p / eq_opp`（相对强弱） |
| `n_rifle` | Int32 | 持长枪（步枪/狙/机枪）的人数 |
| `spend_p` | Float64 | **人均本轮实际花费**（`item_events` 的 cost 汇总） |
| `cash_p` | Float64 | 人均剩余资金（freeze 末） |
| `spend_ratio` | Float64 | 全押程度：`spend_p / (spend_p + cash_p)` |

### 分类规则

```
pistol : 半场首回合（全员带入装备值只剩免费手枪）
eco    : spend_p < 500                        —— 没投入：攒钱 / 保枪
full   : eq_p >= 4000 且 n_rifle >= 3         —— 绝对达标：多数人有长枪
full   : eq_p >= 3000 且 eq_p >= 0.85*eq_opp  —— 相对不亏：对得起这回合
force  : 其余                                  —— 投入了但明显劣势：硬顶
```

**为什么需要三个观测量**：只看「自己买了多少钱」无法区分「同样一套微冲+甲」到底算
“全买”还是“强起”——

| 回合 | 自己 | 对手 | 应有分类 |
|------|------|------|---------|
| 2 CT | 人均 3500，花费 2250（剩 870） | 仅手枪，人均 1370 | **full**（经济上限内的买满/反 eco 买） |
| 17 CT | 人均 3930，花费 3220（剩 130） | 全 AK+AWP，人均 5060 | **force**（真·强起） |

两者装备金额几乎一样，唯一实质差别是**对手强弱**，所以 `eq_opp` 是必需品。

### 可调阈值（`src/analysis/economy.py` 的 `BUY_RULES`）

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `eco_spend_max` | 500 | 人均花费低于此值视为没在买 |
| `full_eq_min` | 4000 | 全买的绝对装备门槛 |
| `full_rifle_min` | 3 | 长枪人数门槛（半数以上） |
| `full_ratio_min` | 0.85 | 相对判据：达到对手装备的 85% |
| `full_rel_eq_min` | 3000 | 相对判据的绝对下限（防止“双穷局”被误判 full） |

> 把 `full_rel_eq_min` 改成 2000 ，“双方都很穷但一方相对占优”的局会从 `force` 变成 `full`。
> 这是个战术术语取舍，已有测试（`tests/test_economy.py`）固定默认行为。
