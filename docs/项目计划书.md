## 1. 项目概述

本项目以《反恐精英》（CS2）为背景，构建一个从 **demo 文件解析 → 数据建模 → 战术分析 → 个性化站位推荐 → LLM 报告生成** 的完整数据科学系统。

系统读取玩家 POV 与比赛 demo，输出：

- **走位热力图**：玩家/车队在特定地图上的站位分布
- **交火 / 死亡热区**：击杀与死亡发生的空间分布
- **战术倾向分析**：开局路线、进攻/防守风格、回合节奏
- **失守区域定位**：经常先丢人、导致回合失败的区域
- **站位与战术建议**：基于历史数据的个性化推荐
- **自然语言战术报告**：由大模型生成的、可读的战术解读

## 2. 背景与动机

### 2.1 个人动机

- 对 CS 这款游戏有持续热情，熟悉地图、战术与职业比赛
- 希望用计算机专业知识解决一个自己真正关心的问题
- 需要一个能体现 **数据工程 + 数据科学 + 机器学习 + 大模型** 完整能力的大型项目

### 2.2 行业背景

- CS2 拥有庞大的玩家与观众基础，职业比赛产生海量公开 demo 数据
- 市面已有 Leetify、Scope.gg 等分析工具，但多为**描述性统计与可视化**
- **个性化推荐 + LLM 自动解读** 是相对稀缺的差异化能力

### 2.3 技术动机

- demo 数据是结构化的时空序列数据，非常适合做数据科学与机器学习
- "站位建议"可以形式化为经典的**推荐系统问题**，直接对应学习方向
- 大模型可以把结构化分析结果转化为自然语言，体现大模型落地能力

## 5. 技术可行性分析

### 5.1 Demo 解析（关键依赖）

| 组件      | 工具                                 | 说明                                                 |
| ------- | ---------------------------------- | -------------------------------------------------- |
| Demo 解析 | `awpy`（Python）                     | CS:GO/CS2 分析专用库，底层为 Go 实现的 `demoinfocs-golang`，性能高 |
| 地图底图    | `awpy` 内置地图数据 / radar 图            | 热力图需要坐标与底图对齐                                       |
| 数据来源    | 个人 Faceit/官匹 demo、**HLTV 职业 demo** | 职业 demo 免费下载，适合构建"高水平基准"                           |

**结论**：解析层有成熟开源方案，无需从零解析二进制文件。项目重心应放在**解析之后的分析与建模**上。

### 5.2 关键数据能力

`awpy` 可提取：

- 每一 tick 的玩家坐标（10 个玩家，每秒数十 tick）
- 击杀 / 死亡 / 助攻事件
- 回合边界与回合结果
- 武器、道具（手雷）使用
- 经济状况（装备价值）

以上数据足以支撑热力图、聚类、推荐与报告生成。

## 7. 数据模型设计

### 7.1 核心表结构（概念设计）

| 表名 | 关键字段 | 说明 |
|------|---------|------|
| `matches` | match_id, map, datetime, source | 比赛元信息 |
| `players` | player_id, match_id, team, name | 玩家与队伍 |
| `rounds` | round_id, match_id, round_num, winner, win_type, duration | 回合信息 |
| `frames` | match_id, tick, player_id, x, y, z, hp, weapon | 玩家坐标序列（体量最大） |
| `events` | match_id, tick, type, actor, victim, weapon | 击杀/死亡/道具事件 |
| `zones` | map, zone_id, x, y, label | 地图区域划分 |
| `zone_stats` | map, team, zone_id, deaths, first_kills, round_win_rate | 区域统计（失守分析） |

### 7.2 存储选型

- **原始坐标序列**：Parquet（列式压缩，适合大批量扫描）
- **事件与统计结果**：SQLite / DuckDB（便于查询与聚合）
- 后续可升级为 PostgreSQL

## 9. 推荐系统设计

### 9.1 问题形式化

| 术语 | 映射 |
|------|------|
| User | 队伍 / 玩家（带角色与打法特征） |
| Item | 候选站位（zone 或 anchor 点） |
| Context | 地图、阵营(CT/T)、回合类型（手枪/经济/长枪）、回合阶段（开局/中期/残局）、人数差、经济 |
| Rating | 该站位在相似情境下的历史表现（回合胜率贡献、生存率、击杀交换比、首杀价值） |

### 9.2 三层方法（由浅入深）

**第一层：统计基线（冷启动友好）**

- 按上下文条件概率表统计每个站位在"相似情境"下的胜率
- 直接排序推荐，可解释性强

**第二层：协同过滤 + 内容混合**

- 为队伍构建"打法向量"（rush 频率、默认率、偏好区域等）
- 找相似的高水平队伍，推荐他们常用的高效站位（user-based CF）

**第三层：Learning to Rank**

- 将每次"交火结果"视为隐式反馈（站此位置赢/输）
- 用 LightGBM ranker 或简单 NN 做 pair-wise 排序
- 离线评估用 NDCG、precision@k，对比 baseline 提升

### 9.3 评估（诚实声明）

- **离线评估**：推荐 top-k 站位与"历史真实高胜率站位"的重合度、NDCG、precision@k
- **局限**：无法真实验证"对玩家是否有帮助"，只能证明"与历史胜率一致"
- 将局限写入 README limitations，是加分项

## 10. LLM 战术报告设计

### 10.1 流程

1. 将阶段 2 的统计 + 聚类结果整理为结构化 JSON
2. 构造 Prompt（含上下文、统计数据、约束）
3. 调用 LLM 生成自然语言报告
4. 可选：多模态（热力图图片 + 文本 → 视觉模型解读）

### 10.2 报告示例（目标效果）

> "你们在 Mirage 中路控制率 32%，低于职业平均 51%；第 7、9 局均在 connector 先丢人导致 A 点失守。建议：开局加强中路烟雾配合，将一名队员提前部署至窗口位争夺信息……"

### 10.3 进阶方向

- RAG：将 demo 分析结果向量化，检索相似回合/战术案例
- 多轮对话：用户追问 → 针对性补充分析

| 模块 | 评估指标 |
|------|---------|
| 热力图/统计 | 可视化正确性、与已知事实一致性 |

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| CS2 demo 格式变更 | 解析失败 | 锁定 awpy 版本，关注其更新 |
| 坐标与地图底图不对齐 | 热力图错误 | 早期验证坐标系，优先解决 |
| 数据量不足 | 推荐不稳健 | 大量下载 HLTV 职业 demo 做基准 |
| 项目范围失控 | 烂尾 | 严格按里程碑交付，先跑通再完善 |
| 在线验证困难 | 无法证明推荐有效性 | 诚实声明局限，聚焦离线评估 |
| 在可视化上花太多时间 | 拖慢进度 | 热力图够用即可，价值在模型层 |
